# SCOPECAST — Threat model

> Scope: the current `contracts/src/*.sol` implementation on Base Sepolia (84532), Reactive Lasna
> (5318007) and Unichain Sepolia (1301), with verified receipts in `DEPLOYMENTS.md`. Testnet-only.
> Residual risk is stated honestly — this is not a claim of an external audit or of atomic
> cross-chain revocation.

Assumptions: the pinned Reactive Omni library (`reactive-lib-omni`, tag `v0.1.0`, commit
`3ade0dcf1d27e67e5783ef807e73a1b9e0c0cce8`) and the official system contract/proxy addresses are
genuine; the deployer verifies them by RPC before broadcasting (`RUNBOOK.md`).

| # | Threat | Attack path | Mitigation in code / operation | Residual risk |
| --- | --- | --- | --- | --- |
| 1 | **Compromised agent** | Stolen agent session key calls `GuardedDeFiVault.rebalance` with a large amount, a wrong selector, a wrong target or after expiry. | Vault checks `active`, `msg.sender == policy.agent`, chain, `destinationModule == address(this)`, `allowedSelector == this.rebalance.selector`, `block.timestamp <= expiresAt`, `0 < amount <= maxValue`, and `amount <= holdings`; `nonReentrant`; no recipient- or target-bearing agent entry point; owner-only `seed`/`withdraw`. (`GuardedDeFiVault.t.sol` covers every rejection path.) | The compromised key can still perform actions within the *current* scoped policy until a revoke callback is confirmed. The maximum loss per action is bounded by `maxValue`, and the total bounded by `holdings` and the expiry. Actions already settled cannot be reversed. |
| 2 | **Malicious source owner** | Owner uses `updatePolicy` to install a wider cap, a new agent or `active=true` for an agent that should be revoked, then the mirror accepts the higher epoch. | `onlyOwner` is the only authority; the agent can never modify its own policy; every mutation increments the epoch and emits a canonical-hash event, so the change is visible and ordered. Operational control: source owner **should be a multisig or smart account in production**, with a policy-review process. | A genuinely compromised or malicious owner is authoritative by design: it can widen a capability or reactivate a revoked one at a higher epoch. This is a governance/key-management risk, not something the contracts can remove. The destination admin has `emergencyRevoke` as a local break-glass action. |
| 3 | **Forged callback** | An EOA calls `PolicyMirror.applyPolicy` directly, or a different reactive contract delivers a payload through the proxy with a spoofed first argument. | `onlyServiceProvider` requires `msg.sender` to be the official Unichain callback proxy `0x775c9B990ADe401060B78D0e98684eEf8d2466C1`; `onlyCallbackSender(reactiveSender_)` requires the network-overwritten first word to equal immutable `_CALLBACK_SENDER`. Hash, chain and approved module are re-checked. (`PolicyMirror.t.sol::test_eoaCannotCallCallback`, `test_proxyButWrongReactiveSenderIsRejected`.) | If the official proxy itself were compromised, both checks would pass; that is a network-level assumption. A wrong `_CALLBACK_SENDER` at construction is unrecoverable without redeploy (see threat 10). |
| 4 | **Spoofed origin event** | An attacker emits a look-alike `PolicyUpdated` from another contract or chain, or crafts a log with a different topic count to confuse decoding. | `react()` (`onlySystem`) checks `chainId == 84532`, `contractAddress == originHub`, `topic0 == 0xd1601cdc…d8c9`, `opCode == 4`, nonzero `agentId`/`agent`/`epoch`, destination chain/module, nonzero selector/cap, and recomputed `PolicyHash`. Irrelevant logs return silently so a revert cannot be used to disrupt billing. (`ScopeCastReactive.t.sol::test_ignoresWrongChain`, `test_ignoresWrongEmitter`, `test_ignoresWrongTopic`, `test_ignoresWrongTopicCount`, `test_ignoresTamperedPolicyHash`.) | The origin hub is a single point of trust: a malicious owner can emit a valid event (threat 2). The subscription is created in the constructor and can be replaced by the owner-only `configure()` function, which unsubscribes the old hub and subscribes the new one without redeployment. |
| 5 | **Stale callback** | A delayed callback carrying an older epoch arrives after a revoke and tries to set `active=true` again. | `PolicyMirror.applyPolicy` ignores `epoch <= storedEpoch` with `StaleCallbackIgnored` and no state change; `ScopeCastReactive` also refuses to request a callback for `epoch <= latestRequestedEpoch[agentId]`. (`PolicyMirror.t.sol::test_oldCallbackCannotReactivateRevokedPolicy`, `testFuzz_epochsAreMonotonic`.) | The mirror's `emergencyRevoke` advances the local epoch independently; if it overtakes the source epoch, legitimate source callbacks at lower epochs are ignored until the source catches up (operational trade-off, documented in `SECURITY.md`). |
| 6 | **Replay / duplicate delivery** | The same log is delivered twice, or the callback proxy retries a delivery. | Reactive watermark `latestRequestedEpoch` suppresses duplicate *requests*; the mirror's strictly-newer rule makes duplicate *deliveries* idempotent and non-reverting, so they do not waste the receiver's gas reserve. (`ScopeCastReactive.t.sol::test_duplicateEventDoesNotRequestSecondCallback`, `PolicyMirror.t.sol::test_staleCallbackIgnoredWithoutStateChange`.) | Replay of a **failed** callback at an already-requested epoch is not automatically re-requested; recovery is manual (threat 7). |
| 7 | **Callback debt / funding exhaustion** | The mirror's native ETH reserve runs out; the proxy bills a failed callback and records debt, so further callbacks are not delivered. | Fund `PolicyMirror` with Unichain Sepolia native ETH; keep a reserve; monitor callback receipts; `PolicyMirror.coverDebt()` is a public wrapper over `AbstractPayer._coverDebt()` that pays outstanding debt from the mirror's balance. Callback gas limit is immutable at deploy (>= 100,000; network cap 900,000). See `CALLBACK_OPERATIONS.md`. | Failed callbacks are still charged. `ScopeCastReactive` exposes a public `coverDebt()` wrapper, so reactive-side debt can be cleared by anyone from the contract balance; keep the reserve funded. A callback requested but never delivered stays at a consumed source epoch (manual recovery required). |
| 8 | **RPC / indexer outage** | Base, Lasna or Unichain RPC fails or lags; the dashboard cannot read events, or an operator wrongly infers success from a stale view. | The console reads state on request and renders `UNKNOWN` / `DESTINATION_SYNC_UNKNOWN` when an address is unset or an RPC is unreachable; `apps/web/public/evidence/flow.json` is updated only from independently checked receipts and is currently `verified: true`. The indexer is display-only; it never submits destination updates. | An outage delays operator visibility, not the on-chain Reactive path itself. A delayed dashboard can make a propagation window look longer than it is; measure latency from receipts, not UI timestamps. |
| 9 | **Race window** | The agent submits a guarded action on Unichain just before the revoke callback is confirmed; the action is included while the old epoch is still active. | Short policy expiry as a fail-safe; strictly-newer epochs on the mirror; vault reads the mirror on **every** call and fails closed once the newer inactive epoch lands. The demo explicitly shows the pre-revoke action succeeding and the same call failing afterwards. | The in-flight action cannot be reversed — there is no atomic cross-chain revocation. SCOPECAST never claims otherwise. The only mitigation for highly sensitive funds is a short `expiresAt` and operational monitoring. |
| 10 | **Immutable misconfiguration** | Wrong owner/module/proxy/reactive/callback-gas values are passed to constructors; or the harness placeholder address is used on a live chain. | Constructors validate zero values and the reactive constructor rejects gas limits below 100,000; deploy from predicted CREATE addresses computed from verified deployer nonces, then verify `eth_getCode` and constructor views (`RUNBOOK.md`). The local harness uses `vm.etch`/`vm.prank` and a placeholder reactive address and must **never** be replicated on-chain. | Immutables cannot be patched: a wrong callback proxy, `_CALLBACK_SENDER`, vault module, hub address or topic0 requires redeployment of the affected contract and re-bootstrap. `setDestinationMirror` is a mutable exception and must be monitored as a privileged slot. |

## Severity framing

| Threat class | Standalone impact | Notes |
| --- | --- | --- |
| Compromised agent | Medium–High | Bounded by cap, holdings and expiry; no arbitrary target or recipient. |
| Malicious source owner | High | Authoritative by design; multisig is the primary mitigation. |
| Forged callback / spoofed origin event | High if successful | Two-modifier callback auth and `onlySystem` + field checks are mandatory. |
| Stale callback / replay | Medium | Prevented by epoch rules; idempotent handling avoids gas waste. |
| Callback debt | Medium–High | Can halt propagation; reserve monitoring and top-up required. |
| RPC/indexer outage | Low–Medium | Visibility only; the console must keep showing `UNKNOWN`. |
| Race window | Medium | Inherent to asynchronous cross-chain systems; no retroactive reversal. |
| Immutable misconfiguration | High | Unrecoverable without redeploy; preflight prediction and verification are essential. |
